# hexextra

[咒法学](https://github.com/gamma-delta/Hex-Mod)(Hex Casting)的附属模组,
给咒术加上几枚**像编程语言那样**的图案:循环、条件分支、多路分派。

全部使用 **Java** 实现(咒法学本体是 Kotlin 写的),并配有完整的中文注释。

## 功能

三枚图案各自都配了算术重载,所以它们在栈上**可自由拆装** —— 可以被当作数据传递、
拆开、重新拼起来,再拿去执行。

### 佛尔之策略(for 循环)

图案 `aeqqqqqawwd`

从栈上取「循环次数」和「代码块」,把代码块重复跑该次数。循环本身不耗媒质;
次数 ≤ 0 时什么都不做,上限 10000 次。循环体与外界共用同一个栈,每轮接着上一轮继续;
在循环体里画「卡戎之策略」可提前跳出。

### 伊芙艾儿丝之策略(if / elseif / else 条件链)

图案 `aedaqda`(建链)、`aedaqdaaw`(建仅 else 链)

从栈上取「条件代码块」和「代码块」拼成一条条件链。**它只是把链放到栈上**,
要在链上画「赫尔墨斯之策略」才会执行。执行时依次求值各分支条件,条件块必须**恰好**
留下一个布尔值;第一个为真的分支执行自己的代码块,都不成立时才执行 else。

用「加法之馏化」把后续的 elseif 与 else 接上去。

### 斯维奇之策略(switch 多路等值分派)

图案 `dawwaqw`(造一条 case)

执行时**直接消费栈顶那个值**去查表,命中哪条 case 就只跑那一条 ——
不贯穿(箭头式语义),因此不需要 break。

- **case 只能是常量**:数值、布尔、null、图案
- **一张表只匹配一种类型**,由第一条 case 推出;塞错类型当场报错
- 重复的 case 报错
- default 用「加法之馏化」接:`add(表, 列表)`

与 if-else 链的关键差别在性能:if-else 链的**每个条件都是一次独立的代码块求值**,
而 switch 是 **0 次代码块求值 + 1 次哈希查表**,分支越多差距越大。

## 环境要求

| 项 | 版本 |
|---|---|
| Minecraft | 1.21.1 |
| NeoForge | 21.1.256 |
| Hex Casting | 0.12.0-devel-pre-64 或更高 |
| JDK | 21 |

## 构建

```bash
./gradlew build
```

产物在 `build/libs/`。

> **注意**:Hex Casting 1.21.1 至今没有发布到任何公共 Maven,只能从作者 CI 取。
> 本项目在 `build.gradle` 里用一个指向 `ci.blamejared.com` 的 Ivy 仓库声明这个依赖,
> 版本号固定在 `gradle.properties` 的 `hexcasting_ci_build`(用固定构建号以保证可复现)。
> 因此**首次构建需要能访问该 CI**。

其余前置(paucal / architectury / patchouli / caelus / inline / cloth-config /
kotlinforforge / curios)都是常规 Maven 依赖,不需要手动下载。

## 手册

三枚功能都写进了咒法学自带的**咒术笔记**,归类在「简易图案」下:

- 简易元运行(for 循环)
- 简易逻辑判断(if / elseif / else)
- 简易多路分派(switch)

书中同时列出了它们各自被重载的原有图案(加法之馏化 / 切除器之馏化 /
外科医师之提整 / 选择之馏化 / 长度之纯化 等)在作用于这些新类型时的语义。

## 开发约定

见 [AGENTS.md](AGENTS.md)。其中几条值得外部贡献者留意:

- **先查清 API 真实签名再写代码** —— 不凭记忆推断 Minecraft / NeoForge / 咒法学的类与方法
- **全部 Java + 中文注释**,注释要说明「实际起什么作用」而非逐字翻译
- **一个功能一个文件夹**,基础设施放 `core/`
- 语言文件等 Minecraft 资源必须遵循固定目录结构,不能跟着功能文件夹走
